# مسار التصميم للمخرجات العربية

## النطاق
كل مخرَج بصري: العروض التقديمية، والملصقات، والمطويات، والإنفوجرافيك، وصفحات HTML، والواجهات، ولوحات المؤشرات والرسوم البيانية، وتصاميم Canva.

هذه المهارة لا تصمم بنفسها؛ تحدد أي مهارة تُستدعى، ومتى، وبأي ترتيب. أسماء المهارات قد تظهر في القائمة مسبوقة باسم الإضافة، مثل `design:design-critique`.

## ترتيب الأولوية عند التعارض
1. السرية والمشروعية: لا يُرفع محتوى غير منشور إلى خدمة خارجية دون طلب صريح.
2. ضوابط التصميم الثابتة أدناه.
3. هوية المستخدمة البصرية، إذا أرفقتها في الطلب أو كانت متاحة في المشروع.
4. توجيهات مهارة التصميم المستدعاة.

تعليمات المستخدمة في الطلب الحالي تعلو على ما سبق، ما لم تخالف البند (١).

## ضوابط التصميم الثابتة
| الضابط | التطبيق |
|---|---|
| اتجاه RTL كامل | تبدأ القراءة والتخطيط من اليمين: الشبكة، والجداول، ومسارات التدفق، وترقيم الخطوات |
| لا نص داخل الصور | النص في طبقة نصية قابلة للتحرير؛ الصورة للتوزيع الهندسي والرموز المؤسسية فقط |
| توزيع هندسي ورموز مؤسسية | أشكال هندسية، وشبكات، وأيقونات خطية بسيطة؛ دون صور توضيحية مزدحمة |
| لا اختلاق بصري | لا تُخترع ألوان أو شعارات أو هوية؛ تُستخدم هوية المستخدمة عند توفرها، وإلا لوحة محايدة يُصرَّح بأنها مؤقتة |
| لا علامات توليد | لا رموز تعبيرية، ولا أسهم أو شرطات طويلة داخل النصوص، ولا علامات مائية أو بيانات تعريف دالة على أداة التوليد |
| قابلية التحرير | عناصر أصلية قابلة للتحرير بدل الصور المسطحة، خاصة في PowerPoint |

## الحد الأدنى للجودة
قبل أي تنفيذ أو تعديل بصري، يُقرأ الملف `references/design-floor.md`: فحوص التباين والمسافات والطباعة وRTL على الناتج المعروض، وقائمة العادات التي تُتجنب، مثل البطاقات المتكررة والرموز التعبيرية بدل الأيقونات والأرقام التوضيحية المعروضة كأنها حقيقية.

## المسار حسب نوع المخرَج
| المخرَج | التسلسل |
|---|---|
| عرض تقديمي | `formal-writing-ar` للنص، ثم مهارة العروض المتاحة، ثم `design:design-critique`، ثم فحص الملف بأداة `arabic-rtl-docs` |
| صفحة HTML أو واجهة | `formal-writing-ar` للنص، ثم `frontend-design`، ثم البناء، ثم `design:design-critique` و`design:accessibility-review`، ثم فحص الملف |
| لوحة مؤشرات أو رسم بياني | `dataviz` قبل أول سطر في الرسم، ثم مسار صفحة HTML |
| تصميم في Canva | `canva:get-design-feedback` للمراجعة، و`canva:edit-design` للتعديل، و`canva:brand-check` عند وجود هوية مسجلة، ونصوصه وفق `formal-writing-ar` |
| ملصق أو عنصر بصري ثابت | الضوابط الثابتة، ثم المراجعة البصرية، ثم التصدير، ثم الفحص |
| مشروع متعدد المخرجات | `superpowers:writing-plans` لخطة المخرجات قبل التنفيذ، ثم المسار المناسب لكل مخرَج |

## الأسئلة قبل التنفيذ
- لا تُطرح أسئلة إذا كانت المعطيات كافية؛ يُختار الافتراض الأنسب ويُذكر في سطر واحد.
- عند الحاجة: جولة واحدة، ثلاثة أسئلة على الأكثر، وفقط عمّا يغيّر المخرَج فعلًا، مثل الجمهور أو الغرض أو المقاس.
- تُستخدم `superpowers:brainstorming` فقط عند طلب فكرة تصميم جديدة غير محددة، ووفق حد الأسئلة نفسه.

## التحقق قبل التسليم
- [ ] عُرض المخرَج أو صُوّر وفُحص بصريًا، لا من الشيفرة وحدها.
- [ ] استوفى فحوص `references/design-floor.md`، ولا يحتوي عادة من قائمة ما يُتجنب دون طلب صريح.
- [ ] الاتجاه من اليمين في كل العناصر، والمصطلحات الإنجليزية معزولة دون انقلاب.
- [ ] لا نص داخل الصور.
- [ ] تباين الألوان مقروء، وحجم الخط مناسب للعرض.
- [ ] النصوص مستوفية قائمة مراجعة `formal-writing-ar`.
- [ ] الملف مفحوص بأداة `arabic-rtl-docs`: لا رموز غير مرئية، ولا بيانات تعريف دالة على أداة التوليد.

## ما لا تفعله هذه المهارة
- لا تستبدل مهارات التصميم المتخصصة؛ تنظّم استدعاءها.
- لا تنقل محتوى إلى أدوات أو مواقع خارجية دون طلب صريح.
